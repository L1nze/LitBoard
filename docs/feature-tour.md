# LitBoard 功能导览

这份导览用一组短 GIF 展示 LitBoard 的主要工作流。每段只讲清一件事：从哪里开始、完成了什么、结果出现在哪里。

> GIF 素材正在制作。下方的拍摄清单同时也是导览的正式结构；素材完成后，将每节的“演示目标”替换为对应画面。

## 1. 从浏览器收藏文献

**演示目标：** 在论文页面打开 LitBoard 扩展，确认文献信息与保存文件夹，一键收入资料库，并在 LitBoard 中看到新条目和 PDF。

建议文件名：`01-browser-save.gif`

## 2. 从 Zotero 迁移资料库

**演示目标：** 打开 Zotero 导入向导，选择资料库，查看导入预览，完成导入后展开原有文件夹与附件。

建议文件名：`02-zotero-import.gif`

## 3. 拖入文件夹批量导入

**演示目标：** 把一个分类整理好的文献文件夹拖到左侧栏空白处（或某个文件夹行上），目录树原样变成 LitBoard 的文件夹结构（空分支自动剪去），其中的 PDF 自动识别元数据、去重建立条目并进入全文检索；源文件全程只复制不移动。

建议文件名：`03-folder-drop-import.gif`

## 4. 阅读与批注 PDF

**演示目标：** 双击文献进入阅读器，选中一段文字并高亮，再添加一条便签，最后在右栏看到批注列表。

建议文件名：`04-pdf-annotation.gif`

## 5. 把批注加入笔记

**演示目标：** 从批注列表选择“加到笔记”，打开笔记查看摘录与出处，再点击出处回到 PDF 中的原位置。

建议文件名：`05-annotation-to-note.gif`

## 6. 搜索全文并跳到原文

**演示目标：** 输入一个能同时命中文献、笔记和 PDF 正文的关键词，切换结果类型，并从全文结果跳到命中页面。

建议文件名：`06-full-text-search.gif`

## 7. 用智能文件夹整理资料

**演示目标：** 组合年份、标签和附件条件，查看筛选结果，将条件保存为智能文件夹，再次点击即可恢复结果。

建议文件名：`07-smart-folder.gif`

## 8. 让 AI 助手查找并阅读文献

**演示目标：** 提交一个简短研究问题，展示助手检索文献、打开全文、给出带来源的回答，再把选中的论文加入资料库。

建议文件名：`08-ai-research.gif`

## 9. 查看引用关系图

**演示目标：** 围绕一篇论文生成引用关系图，点击节点查看文献信息，调整视图并导出结果。

建议文件名：`09-citation-graph.gif`

## 10. 在 Word 中插入引文

**演示目标：** 在 Word 光标处打开 LitBoard 引文面板，选择两篇文献，插入合并引文，再生成参考文献表。

建议文件名：`10-word-citation.gif`

## 11. 同步与备份

**演示目标：** 展示坚果云同步状态，手动完成一次同步，再打开备份页面查看最近的快照。

## GIF 导览如何制作

### 先按用户任务分段

不要录一条从头到尾的长动画。每个 GIF 只保留一个完整动作，建议控制在 **6–12 秒**：

1. 开始画面先停留约 0.5 秒，让读者看清入口；
2. 鼠标完成 2–5 个关键动作；
3. 结果出现后停留约 1 秒；
4. 结束画面尽量能自然接回开始画面，循环播放时更顺滑。

推荐先制作最能说明 LitBoard 特点的 6 条：浏览器收藏、PDF 批注、批注进入笔记、全文搜索、AI 调研、Word 引文。其余内容可以随后补齐。

### 统一录制环境

- 窗口内容区固定为 **1280 × 720**；最终 GIF 可缩放到 960 像素宽；
- Windows 显示缩放固定为 100%，LitBoard 使用同一套浅色主题；
- 准备一个专门的演示资料库，文献数量保持在 20–40 篇；
- 文献题名、作者、标签和笔记使用可公开展示的内容；
- 文件路径、账号、令牌、模型 Key、同步地址和个人姓名不进入画面；
- 每次录制前恢复相同的窗口布局、文件夹选择和阅读位置；
- 鼠标移动放慢，点击前短暂停顿，避免来回寻找入口。

### 推荐工具链

录制可使用 ScreenToGif、OBS Studio 或 ShareX。最省步骤的组合是：

1. 用 **ScreenToGif** 按固定区域录制；
2. 删除等待过长、误点和重复帧；
3. 把帧率调整到 **10–15 fps**；
4. 导出 GIF 后用 **gifsicle** 进一步压缩；
5. 如果颜色较多或文件仍然过大，同时导出 WebP，供官网或发布页使用。

使用 gifsicle 的示例：

```powershell
gifsicle -O3 --lossy=60 --colors 128 `
  docs/assets/feature-tour/04-pdf-annotation.gif `
  -o docs/assets/feature-tour/04-pdf-annotation.gif
```

建议每个 GIF 控制在 **5 MB 以内**，核心演示尽量控制在 **2–3 MB**。如果压缩后文字明显发糊，先缩短时长或裁小画面，再减少颜色。

### 素材目录

统一把素材放在：

```text
docs/
├─ feature-tour.md
└─ assets/
   └─ feature-tour/
      ├─ 01-browser-save.gif
      ├─ 02-zotero-import.gif
      ├─ 04-pdf-annotation.gif
      └─ ...
```

素材加入后，每一节使用相同格式：

```markdown
## 4. 阅读与批注 PDF

选中文字即可高亮、添加便签或收入笔记，所有批注集中显示在阅读器右栏。

![阅读与批注 PDF](assets/feature-tour/04-pdf-annotation.gif)
```

### 给每条 GIF 配一句结果说明

GIF 负责展示动作，文字负责告诉读者价值。说明句建议使用“动作 + 结果”的写法：

- “选中正文并高亮，批注立即出现在右栏。”
- “把批注加入笔记，点击出处即可回到原文。”
- “搜索一个关键词，同时找到文献、笔记、批注和正文。”

避免逐帧解释按钮位置，也不用罗列实现方式。

### 录制完成后的检查

- 第一帧能看懂功能从哪里开始；
- 最后一帧清楚展示完成结果；
- 循环播放没有明显跳动；
- 鼠标没有遮住菜单、文字或结果；
- 字体在 GitHub 页面宽度下仍然清晰；
- 页面中没有个人信息或测试凭据；
- GIF 文件名、章节编号和替代文字一致；
- README 中只放 1–2 条代表性 GIF，其余统一链接到本导览，避免首页加载过慢。

## 推荐的首页呈现方式

README 首页保留最有代表性的两段即可：

1. “批注进入笔记并返回原文”，展示 LitBoard 的阅读闭环；
2. “AI 查找、阅读并收藏文献”，展示调研助手的完整动作。

两段 GIF 下方放一个“查看完整功能导览”的链接。这样首页打开快，完整演示也有清晰入口。
