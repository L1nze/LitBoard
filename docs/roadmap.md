# LitBoard 路线图（开源前完善与长期演进）

> 本文档是《LitBoard 开源前完善与长期演进计划》的可执行版本。任务 ID（M0–M8）与待开发功能 ID（B-*）长期有效，
> 执行状态统一记录在 [task-ledger.md](task-ledger.md)，证据与基线记录在 [audit-baseline.md](audit-baseline.md)。

## 定位

LitBoard 是 Windows 上本地优先的个人科研主力工具，覆盖收集、整理、检索、阅读、笔记、引用与数据恢复。
采用渐进改进，保留 Electron、现有数据契约和本地优先架构。

已确认的方向约束：

- 视觉克制、专业，保留高效三栏布局；1000 篇为日常基线，1 万篇为正式验收规模，5 万篇为压力测试。
- 先达到开源发布门槛（M5），再持续完善体验与高阶功能。
- 不做：跨平台重写、移动端、团队协作、插件市场、大型 AI 平台。
- 总体判断：功能广度已完整，短板在**可靠性、交互一致性、性能验证和发布质量**。

## 里程碑

### M0 基线与交接材料
- `docs/roadmap.md`（本文）、`docs/audit-baseline.md`（证据）、`docs/task-ledger.md`（状态）。
- 问题标记三态：**代码已确认** / **运行已复现** / **待验证**，禁止混用。
- 生成确定性隔离测试数据（1k / 10k / 50k 篇）的脚本与样本库；许可明确的 PDF/EPUB/快照样本。
- 验收：接手者不接触真实用户库即可重现测试数据与基线。

### M1 编辑安全、弹窗与关闭可靠性
- 弹窗栈：Esc 只关最顶层；初始焦点、焦点圈定、关闭后返回焦点。
- 编辑器独立草稿：保存前不改正式实体；草稿本机持久化、不进同步正文；保存/放弃后清理。
- 退出握手改为「关闭请求 → 渲染层等待保存确认 → 放行关闭」；保存失败保留窗口与草稿可重试；
  网络同步不得无限阻塞退出。
- 验收：嵌套弹窗 Esc、取消、点击关闭、Alt+F4、编辑后立即退出、磁盘写失败、离线均有端到端验证；
  正常关闭再启动后数据一致。

### M2 开源安全与可信构建
- `scripts/ensure-tools.ps1` 核对外置工具版本（空缓存/版本不符/半安装/离线失败）；
  保持零 `node_modules` 与 PowerShell BOM。
- 审查 Electron / PDF / vendor 依赖支持状态；先修工具漂移，再谈升级。
- IPC 统一受信窗口与顶层 frame 校验；区分用户选择的外部附件、受管文件与不可信导入路径。
- 扩展桥接确定 Host/Origin 策略，保留 token 验证（当前 CORS `*` 不得表述为已证实绕过）。
- 检查快照 / 富文本 / EPUB / ZIP / 外链 / 下载重定向 / 日志的信任边界。
- 第三方组件台账（版本、来源、哈希、许可证、NOTICE）；安全文档去掉占位邮箱。
- 验收：恶意路径、非法来源、错误 token、畸形载荷、超大导入、不可信 HTML 的负向测试通过。

### M3 首版发布核心可用性
- 窄窗（≤1220px）PDF 搜索不再被隐藏，改为可唤出入口；工具栏主操作 +「更多」分组。
- 批注 / 笔记 / 附件结果分页（默认 100 条/页），ID 索引消除逐项全库查找。
- 核心工作流键盘可达；区分空库 / 空文件夹 / 无结果 / 加载失败 / 离线状态。
- 失败信息从短暂 toast 升级为可找回（通知中心）；成功提示保持轻量。
- 可跳过的首次使用清单，离线可完成导入、阅读、笔记、导出。
- 修正文档与界面中与实际能力不符的描述。
- 验收：1080 / 1280 / 1920 宽 × 100% / 125% / 150% 缩放下关键操作可达；十万批注结果 DOM 有界。

### M4 性能与资源专项
- 启动、完整性检查、加载、保存、检索、PDF 首屏、关闭分段计时，形成可复现基准。
- PDF 首屏优先渲染；MuPDF.js Worker 单内核（保留 epoch / 取消 / 原位 relayout 契约）。
- 局部保存改造为实体变更批次；按变更范围刷新视图；可见页集合维护；重型脚本按需加载。
- 约束：不得删完整性检查、关备份、忽略冲突、降批注准确性或无限缓存换性能；每项优化附前后数据。
- M5 门槛仅要求「基准已建立且无阻塞日常操作的问题」；Worker 化等深水区可后置。

### M5 开源预览发布门槛（依赖 M1–M3 完成 + M4 基准）

- 首版手动升级流程；代码签名 / 商店 / 自动更新另立任务。

### M9 AI 调研助手（进行中；架构与三期计划于 2026-09-19 定稿）

定位：与正式库**分库**的调研子系统——持久化调研库保存检索发现的文献全集（身份/元数据/引用边），
正式库仍是用户收藏的子集；会话目录保存对话与产物（长期成果，独立于可清理缓存）；引文网络是双入口
共用模块。已定关键决策：身份为代理键永不变更（外部 ID 走 ext_ids 索引）、`paper.researchIds` 落实体
随同步走（二期 schema v14）、快照只存身份核（整库可重建不进快照）、LLM 单一 OpenAI 兼容配置
（Base URL 校验 https/localhost 豁免）、向量是可选加强项默认关（B-1 借此扶正）、回填链
OpenAlex→Crossref→Elsevier abstract（Elsevier 限单并发 ~1.1s、配额错误记账停批）。

- **一期（已完成）**：调研库存储层（research.db + vec.db 空壳 + works_fts）+ 一次性导入 harness 库

  SSE 流式 + 会话目录系统（session.json/index.json/md 生成物/回收站删除）+ 右侧抽屉 UI（历史分组/

- **二期**：schema v14（`paper.researchIds`）+ 收藏桥（dlgConfirm 确认 → addPapers 去重）+ B-1 向量

### M9-4 科研网页检索（四期；2026-09-20 定稿并落地；两项已拍板决策均已实现）

背景：调研库的发现层此前只有结构化学术 API（OpenAlex / Crossref / S2 / PubMed），覆盖不到
非索引内容（预印本聚合页、会议页、机构库、数据集）；且仓库**没有任何 HTML→正文抽取能力**
（readability/trafilatura 类零命中）。业界开源 agent（GPT-Researcher / Hermes 等）的通用模式是
「search → fetch → extract → scrub → LLM」，检索与抽取各自可插拔 provider。

选型结论：采用 **TinyFish**（`api.search.tinyfish.ai` / `api.fetch.tinyfish.ai`，Search 与 Fetch
在其 $0 余额下免费）作为首个网页 provider——其 Search 提供 `domain_type=research_paper` 学术索引
（额外返回作者/期刊/年份/被引数），Fetch 直接返回干净 markdown（自带 JS 渲染与去模板），
**一次性覆盖「抽取器必须新建」与「通用网检缺入口」两个缺口**。

已拍板决策（2026-09-20）：

1. **接受第三方出境**：检索词与抓取的 URL 会经 TinyFish 服务器。落地要求：默认关闭、显式开启、
   首次开启弹出境告知并落 `webSearchEgressAcknowledged`（未确认则不注册工具）。
2. **Fetch 限定公开学术域**：仅允许学术域名白名单内的 URL 交给第三方抓取；域外只保留标题/摘要
   （不抓正文）。白名单为代码内固定后缀表（doi.org / arxiv.org / pmc.ncbi.nlm.nih.gov /
   europepmc.org / biorxiv.org / medrxiv.org / osf.io / zenodo.org / figshare.com / hal.science /
   aclanthology.org / openreview.net / 主流出版商域 + 机构域后缀 `.edu` `.ac.uk` `.edu.cn` `.ac.jp`
   等），不做「任意 https」。

范围：

- **4a 检索**：新建 `js/webfetch.js`（纯函数：学术域判定、结果规范化、响应形状校验、查询构造）
  + `electron/webfetch-net.js`（固定 URL 主机、复用 `createThrottleQueue`、Key 走 safeStorage →
  integrations.json）；`web_search` 只读工具（`domainType` 默认 `research_paper`，支持年份范围）；
  结果按现有范式入库调研库——**响应无 DOI，必须按标题匹配补齐**（复用 enrich 的匹配思路：
  先 DOI、再规范化标题），否则退化成「一堆网页链接」。
- **4b 抓取**：`fetch_page` 只读工具（仅学术域，域外拒绝并说明原因）→ markdown 落
  `kind='snapshot'` 目录型附件（复用现有附件类型与同步/去重体系）→ 入 `pdf_fts`，
  **顺带消掉 limitations 里「网页快照不支持全文检索」那条**；未收藏的调研条目正文落会话附件目录。
- 信任边界：不新增渲染层白名单与 CSP 改动（主进程固定 URL 主机，比照 M9 一期）。
- 静默失败：TinyFish Fetch 的 per-URL 失败（超时/反爬/DNS）**在 HTTP 200 内以 `errors[]` 返回**，
  必须解析 `errors[]` 与响应形状，不得只看状态码；`final_url` 若离开学术域则丢弃该结果并报错
  （我们只能校验自己发出的 URL，重定向发生在对方侧——这点如实写进 limitations）。

验收：① 未开启 / 未确认出境告知时 agent 看不到 `web_search` / `fetch_page`；② 学术域内 URL 可抓回
markdown 并能在全文检索命中；③ 域外 URL 被拒且提示原因（不静默、不偷抓）；④ 构造
「200 + `errors[]`」响应能被识别为部分失败并如实上报；⑤ `final_url` 越域时结果被丢弃；
⑥ 检索结果入库后 DOI 补齐率可量化，无 DOI 者以 URL 作为 ext_id 登记；⑦ 关闭开关后不再有任何
该主机外呼；⑧ 全部文案 T() 覆盖、三门槛全绿。

明确不做：任意 URL 代理抓取（内网外泄面）、Google Scholar 抓取（ToS + 反爬）、出版商付费全文的
自动绕过（403/Cloudflare 是硬墙）、无头浏览器抓取（主窗口禁导航，需新建隐藏窗口，成本与风险均高）、
把 Deep Research 式多跳自动调研做成默认行为（沿用「用户意图触发」原则）。

## 待开发功能（backlog）

> 已决定缓后的功能登记处。启动实施时移入对应里程碑（或新开里程碑），按「执行规则」交付。

### B-1 语义检索扶正：独立向量嵌入接入 + 增量索引 + 成本护栏（**部分作废，2026-09-20 收缩**）

> **范围收缩（2026-09-20，用户决定）**：语义检索不再作为用户面功能存在，**只作为 AI 助手的工具**
> （`semantic_search` / `find_literature` / `search_openalex` 的 `mode=semantic`）。正式库那条链
> ——搜索框 `semantic:` 前缀、`paper_vec` 索引、`semantic:*` IPC、`integrations.embedTexts`、
> 「语义搜索（可选）」设置区、同步配置里的 `semanticEnabled`——**已整体删除**（schema v7 迁移
> DROP `paper_vec`）；「语义检索服务商（段落找文献）」设置区与手动模式的「语义检索」按钮也一并移除，
> OpenAlex / Semantic Scholar 召回常开。因此本条目下列范围中的「搜索框入口 / 全量重嵌 / 存量
> `paper_vec` 迁出」不再适用，**已落地的是「独立向量嵌入接入」那一半**（`js/embedcfg.js` +
> `electron/embed-net.js`，消费方为调研库向量：AI 助手语义检索工具、段落找文献的本地向量召回、
> 空闲增量构建；实现见 `electron/research-build.js` 与 AGENTS.md M9-2/M9-6）。

背景（当时的权宜实现）：嵌入模型写死（Qwen `text-embedding-v3` / OpenAI
`text-embedding-3-small`，`electron/integrations.js` EMBEDDING_PROVIDERS），凭据复用「划词翻译」配置，
没有独立的向量模型接入口；翻译服务商非 Qwen/OpenAI 时报「不支持嵌入接口」。「构建 / 更新语义索引」
为全量重嵌（`js/app.js` buildSemanticIndex），重复点按重复计费。入口为搜索框 `semantic:` 前缀。

范围（保留部分）：
- 独立「向量嵌入」设置区：OpenAI 兼容端点（Base URL + 模型名 + API Key），可接 DashScope / 硅基流动 /
  智谱 / 本地 ollama 等；与划词翻译凭据解耦；提供连接测试与用量预估（按已索引 token 估算）。
- 自动增量构建：向量模型配置就绪时后台自动构建，仅在库空闲（无待保存变更、无进行中同步）时运行；
  按内容 hash（标题+摘要，剔除 updatedAt 类易变字段）跳过未变条目——未做改动不重嵌、不重复计费。
- 成本护栏：失败批次不自动重复计费重试（持久 `embedFailedBatch` 标记）；设置页常驻已索引用量展示；
  本地小模型路线（零 API 成本）列为可选后续项。
- 网络出口：用户自定义 Base URL 属新增出口类型，实施前需先明确信任边界（当前主进程出口仅允许
  integrations 固定 URL 与 ALLOWED_API_HOSTS 白名单两类），不得静默放行任意主机；
  新增固定主机须同步登记白名单与 CSP connect-src。

非目标：全库问答 / LLM 阅读理解（仍是 M8 远期方向，不自动实施）；PDF 正文全文嵌入。

验收：二次构建只嵌入变更条目（嵌入请求数可验证）；断网 / Key 失效时明确报错且旧索引
仍可用于检索；自动构建只在空闲触发，不与保存 / 同步争写；增量判定与嵌入响应解析有 node:test
纯函数覆盖。

## 执行规则（给接手模型）

按 M0 → M8 顺序推进；文档 / 台账 / 测试夹具可并行，共享前端状态与数据协议串行。
每个任务交付：证据 → 最小实现 → 测试或验收记录 → 兼容与回退说明 → 台账更新。
接口演进限定在计划列出的六类（弹窗生命周期、保存收尾、增量实体保存、后台任务状态、PDF Worker 契约、
本地诊断记录）。遵守现有权威模型、同步集合、资产管理、迁移与 relayout 约定。
禁止接触真实用户库、覆盖既有改动、换技术栈、自动发布。
完成标准是**可复现的用户体验与数据可靠性改善**，不是代码量或通过一次单测。

## 拟定验收预算（非当前成绩）
